# M03：文章编辑器设计规格

路由：`/admin/editor`

源码：`app/admin/editor/page.tsx` 及其现有编辑器子组件

模板：Writing Workspace

## 页面任务

让博主专注完成文章创建、编辑、预览和发布，同时清楚掌握保存、草稿恢复和冲突状态。

## 必须保留

- 新建与编辑两种模式。
- 标题、slug、摘要、正文、分类/标签、封面和发布状态等现有字段。
- Markdown 写作、预览、保存草稿与发布流程。
- 本地草稿恢复、离开保护和已有冲突处理。
- 管理员权限、现有 API 与数据结构。

## 信息层级

```text
编辑器顶栏
├── 返回 / 文档标题
├── 保存状态
└── 预览 / 保存 / 发布
写作主体
├── 标题与摘要
├── Markdown 正文
└── 元数据设置
草稿恢复 / 冲突 / 错误反馈
```

正文编辑是绝对主任务；元数据、封面和状态作为侧栏或折叠分区；保存状态始终可见但不抢占视觉中心。

## 版式设计

- 1440 桌面采用主写作区 + 受控元数据侧栏，正文区保持舒适编辑宽度。
- 顶栏保持关键状态和操作可见，避免用户滚动很远才能保存。
- 表单分组使用间距和浅分隔线，不把每个字段包成卡片。
- 预览模式尽量接近公开文章页的排版，但保留清晰的后台身份和返回编辑入口。
- 冲突与草稿恢复使用专门的 Dialog/Notice，不与普通成功 toast 混用。

## 组件边界

- `EditorHeader`：返回、状态和关键操作。
- `EditorCanvas`：标题、摘要和正文。
- `PostMetaPanel`：分类、标签、封面、slug 和发布设置。
- `DraftRecoveryDialog`：本地草稿恢复。
- `ConflictDialog`：远端版本冲突决策。
- `DirtyStateGuard`：复用离开保护行为。

业务状态由页面或专用 hook 编排，纯视觉组件不直接写 Supabase。

## 状态

- 加载文章：保持编辑器骨架，未完成前不可误编辑空文档。
- 未保存：顶栏持续显示；保存成功后切换为已保存时间。
- 自动/手动保存中：不阻塞继续输入，只限制重复提交。
- 草稿可恢复：展示本地与远端时间，允许明确选择。
- 冲突：保留两个版本，不能静默覆盖。
- 发布中/成功/失败：与保存状态分离。
- 会话失效：保留本地内容后再引导登录。

## 交互

- 常用保存快捷键可用并阻止浏览器默认保存页面。
- 标题到正文的 Tab 顺序自然，工具按钮有可访问名称。
- 离开未保存文档必须通过统一确认流程。
- 预览不会触发额外编辑器初始化或丢失光标/滚动。
- 上传封面或资源失败时保留正文和已选文件信息。
- 发布是明确动作；不可由普通保存意外触发。

## 响应式

- 1440：正文与元数据并列，顶栏操作完整。
- 1024：侧栏收窄或可折叠，正文优先。
- 768：元数据转为抽屉/折叠区，顶栏次级操作进入菜单。
- 375：单列写作；标题、正文、保存始终可达；不承诺桌面同等并排预览。

## 不在本页处理

- 不更换 Markdown 编辑器内核，不新增协同编辑或版本历史系统。
- 不修改文章 schema、发布流程或资源存储策略。
- 不为视觉整洁删除现有草稿恢复和冲突保护。

## 验收

- 新建、编辑、草稿恢复、冲突、保存、预览、发布和离开保护均有专项验证。
- 长文、长标题、多标签和上传失败不会破坏编辑状态。
- 公开预览与真实文章排版的核心 token 一致。
- 375px 可以完成基本写作和保存，且无横向溢出。
