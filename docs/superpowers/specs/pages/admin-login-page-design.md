# M01：后台登录页设计规格

路由：`/admin/login`

源码：`app/admin/login/page.tsx`

模板：Focused Admin Auth

## 页面任务

让博主快速、安全地进入内容后台，同时明确区分“访客账户登录”和“站点管理登录”。

## 必须保留

- 管理员邮箱与密码认证。
- 登录成功后的后台返回路径。
- 非管理员、认证失败和提交中的处理。
- 返回公开博客的入口。
- 现有 Supabase 权限判断，不在前端伪造管理员权限。

## 信息层级

```text
站点管理标识
管理员登录标题
邮箱 / 密码
主登录操作
错误或安全说明
返回博客
```

后台标识高于装饰；访客应能立刻知道这里不是普通用户登录页。

## 版式设计

- 使用比公共登录页更克制的窄纸面，不展示内容预览和大面积景观动画。
- 品牌沿用墨色与朱印，但管理员语义通过明确文案表达，不依赖颜色。
- 表单组件与 A01 共用；壳层和返回目标可以不同。
- 错误区域固定在合理位置，避免提交失败导致表单整体跳动。

## 组件边界

- 复用 `AuthShell` 的结构能力，通过 `admin` 变体控制文案和氛围。
- `Input`、`Button`、`Feedback` 与普通登录页一致。
- 权限检查、返回路径和认证提交保留在后台登录页面逻辑中。

## 状态

- 初始、提交中、凭据错误、无管理员权限、成功跳转分别呈现。
- 已登录管理员直接按现有规则进入后台。
- 已登录但无管理员权限时显示明确说明并提供返回博客/普通账户入口。
- 会话检查期间使用稳定占位，避免表单先出现后消失。

## 交互

- Enter 提交；提交中阻止重复请求。
- 错误后聚焦错误摘要或首个需要修正的字段。
- `next` 返回路径只使用已验证的站内目标。
- 密码字段采用正确 autocomplete，不在页面日志或提示中暴露敏感信息。

## 响应式

- 1440/1024：窄表单居中，后台标识清楚。
- 768/375：减少背景装饰，表单占满安全内容宽度，按钮全宽。

## 不在本页处理

- 不新增管理员注册、邀请、找回密码或权限编辑。
- 不改变管理员识别机制与后端策略。
- 不与普通用户登录入口合并为含糊的单一表单。

## 验收

- 普通登录与后台登录在结构一致的同时语义明确不同。
- 权限检查不产生表单闪现或错误页面跳跃。
- 错误、重复提交、无权限和成功返回路径均被验证。
- 375px、键盘和自动填充场景可用。
