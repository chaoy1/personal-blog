# M02：后台文章管理页设计规格

路由：`/admin`

源码：`app/admin/page.tsx`、`app/admin/layout.tsx`、`components/admin/AdminConfirmDialog.tsx`

模板：Admin Collection

## 页面任务

让博主快速掌握文章状态，定位目标文章，并完成新建、编辑、预览、发布状态管理和删除。

## 必须保留

- 后台全局壳层、导航、主题切换和查看博客入口。
- 文章列表、搜索/筛选、状态信息和新建文章。
- 编辑、预览、发布相关操作与删除确认。
- 管理员权限保护和现有 API 行为。
- Phase 2 对后台必要数据的稳定快照规则；后台刷新不清空列表。

## 信息层级

```text
后台导航
页面标题 / 新建文章
搜索与状态筛选
文章集合
├── 标题
├── 状态 / 更新时间 / 分类
└── 编辑 / 预览 / 更多操作
分页或集合状态
```

标题与发布状态是首要扫描信息；次要元数据降级；危险操作隐藏在明确的次级入口中。

## 版式设计

- 桌面采用高信息密度但有节奏的列表或表格式行，不使用大面积内容卡片。
- 工具区固定为标题操作层，搜索和筛选形成第二层。
- 行高允许标题换行一次，操作区宽度稳定，状态 Badge 使用统一语义色。
- Admin Shell 比公共纸面更简洁，但继续使用墨色、纸色和朱印强调。
- 列表刷新时保留行尺寸，避免骨架与真实内容高度差异过大。

## 组件边界

- `AdminPageHeader`：标题、说明与主操作。
- `PostFilters`：搜索与状态筛选。
- `AdminPostList` / `AdminPostRow`：集合与单行。
- `Badge`：草稿、已发布等状态。
- `ConfirmDialog`：统一删除确认。

筛选状态属于页面；文章写作和预览逻辑分别留在 M03、M07。

## 状态

- 首次加载：列表骨架与筛选区同时稳定出现。
- 后台刷新：保留列表、筛选词、当前页和滚动位置。
- 空数据库：强调创建第一篇文章。
- 筛选无结果：保留筛选条件并提供清除入口。
- 错误：有旧数据时保留；无数据时提供重试。
- 行操作中：只锁定目标行；成功后局部更新。

## 交互

- 搜索输入做合理防抖，不因每个字符重置整个页面。
- 行主点击进入编辑；预览和更多操作使用独立按钮，避免嵌套链接。
- 删除必须展示文章标题并二次确认。
- 筛选与分页可恢复，浏览器后退不会丢失上下文。
- 键盘焦点顺序遵循筛选、列表、行操作。

## 响应式

- 1440：完整元数据列和行操作可见。
- 1024：收敛低优先级列，保留标题、状态、时间和主操作。
- 768：工具区可换行，列表转为紧凑行块。
- 375：每篇文章成为单列管理条目；危险操作收进菜单但保持可访问名称。

## 不在本页处理

- 不新增统计看板、访问分析、批量发布或复杂权限管理。
- 不改变文章状态机和数据库字段。
- 不在总览页嵌入完整编辑器。

## 验收

- 大量文章、长标题、空结果和操作失败下布局稳定。
- 搜索、筛选、返回、刷新和分页不造成列表清空闪烁。
- 文章状态不仅依赖颜色表达。
- 375px 可完成新建、搜索、编辑、预览和删除。
