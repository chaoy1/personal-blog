# M05：后台照片管理页设计规格

路由：`/admin/photos`

源码：`app/admin/photos/page.tsx`

模板：Asset Workspace

## 页面任务

让博主分清“创建相册、准备上传、执行上传、整理现有照片”四种任务，并在大量图片下仍能掌握进度和目标。

## 必须保留

- 相册创建与选择。
- 多图片选择、上传队列、说明等现有编辑能力。
- 已有照片的修改、排序/归档和删除能力。
- 上传进度、失败恢复和管理员权限。
- 现有 Supabase Storage 与数据库关系。

## 信息层级

```text
页面标题 / 当前相册
相册选择与创建
上传工作区
├── 文件选择
├── 暂存队列 / 单项状态
└── 执行上传
照片管理区
├── 筛选 / 排序
└── 缩略图 / 说明 / 归属 / 操作
```

当前相册和上传进度是最高优先级；已有照片管理不能与待上传队列混成同一视觉集合。

## 版式设计

- 使用渐进披露：相册区、上传队列、现有照片三个明确工作段。
- 上传队列以稳定缩略图和单项状态呈现，失败项可单独重试。
- 现有照片采用适合管理的规则网格，不使用公共相册页的沉浸式灯箱布局。
- 批量/危险操作固定在其作用范围内，不能漂浮到含糊的全页工具栏。
- 空间紧张时优先保留照片、状态和主操作，低优先级元数据折叠。

## 组件边界

- `AlbumSelector` / `CreateAlbumDialog`：选择与创建相册。
- `UploadDropzone`：文件输入与格式说明。
- `UploadQueue` / `UploadQueueItem`：暂存、进度、错误和重试。
- `PhotoManagerGrid` / `PhotoManagerItem`：已有照片管理。
- `ConfirmDialog`、`Feedback`：统一行为。

上传队列状态与已保存照片状态分离；基础图片选择能力可以复用，业务流程不强行合并。

## 状态

- 相册加载、上传队列、上传请求和照片集合各自拥有状态。
- 上传中保留所有队列项，逐项标记等待、进行中、成功、失败。
- 部分成功时不把整批标记为成功；失败项可重试。
- 切换相册前若队列不为空，明确提示影响。
- 后台刷新保留当前相册、筛选和队列。
- 空相册展示上传入口，不显示错误式空态。

## 交互

- 拖放与文件选择等价，键盘用户可以完成全部上传操作。
- 选择文件后即可删除或编辑暂存项，未确认前不写数据库。
- 删除已有照片必须显示缩略图/说明和存储影响提示。
- 重排如支持拖拽，必须同时提供键盘或按钮替代。
- 大批上传期间页面可继续查看队列，但离开需确认。

## 响应式

- 1440：上传工作区与现有照片可使用宽容器，多列管理网格。
- 1024：缩减网格列数，工具仍在目标区域附近。
- 768：三段任务垂直排列，队列采用单列或双列。
- 375：不依赖拖拽；单项状态与重试按钮完整显示；底部操作避开安全区。

## 不在本页处理

- 不迁移图片存储、不批量压缩历史资源、不改变相册 schema。
- 不新增公开投稿、AI 标签或高级图像编辑。
- 不以视觉重构为由删除现有说明、排序或归档能力。

## 验收

- 空相册、百张照片、批量上传、部分失败和网络恢复均有明确结果。
- 切换相册、刷新和离开不会静默丢弃队列。
- 删除和重排目标明确且可撤销或经过确认。
- 375px 能完成创建相册、选择图片、上传、重试和删除。
