# A01：登录与注册页设计规格

路由：`/login`

源码：`app/login/page.tsx`

模板：Focused Auth

## 页面任务

让访客以最低认知负担完成登录或注册，并明确知道当前模式、提交状态和失败原因。

## 必须保留

- 登录/注册模式切换。
- 邮箱、密码及注册昵称字段。
- Supabase 认证流程和现有跳转规则。
- 全局 Feedback 反馈与返回首页能力。
- 主题切换和基本品牌识别。

## 信息层级

```text
品牌 / 返回博客
登录或注册标题
模式切换
表单字段
主提交操作
状态说明与辅助入口
```

当前模式标题和主按钮必须一致；错误贴近对应字段或表单摘要，品牌氛围不能盖过任务。

## 版式设计

- 使用紧凑的居中纸面表单，背景保留淡化的山水氛围。
- 表单最大宽度稳定，不因登录/注册字段数量变化而横向跳动。
- 模式切换采用 Tabs 语义；选中状态靠字重、墨线与底色共同表达。
- 输入框、按钮、说明文字使用统一 Form Token，不出现第三套圆角和阴影。
- 装饰不进入键盘顺序，也不影响移动端软键盘。

## 组件边界

- `AuthShell`：品牌、返回、容器和背景。
- `Tabs`：登录/注册模式切换。
- `Input`、`Button`、`Feedback`：复用基础组件。
- 页面保留认证提交编排，不把业务流程塞入纯视觉组件。

## 状态

- 初始：清楚标识当前模式。
- 提交中：主按钮显示进行中并防止重复提交，字段内容保持。
- 字段错误：与字段关联并可被屏幕阅读器读出。
- 认证错误：使用用户可理解的说明，不直接暴露后端错误文本。
- 成功：给出明确反馈后按现有规则跳转。
- 已登录：按现有策略跳转或显示返回账户入口，避免继续展示无效表单。

## 交互

- 切换模式保留可复用的邮箱，不保留不应跨模式共享的敏感状态。
- Enter 提交当前表单；提交中禁用重复触发。
- 显示/隐藏密码如实现，必须有文本可访问名称和状态。
- 错误后焦点移动到首个错误字段或错误摘要。
- 浏览器自动填充不破坏输入框背景和标签位置。

## 响应式

- 1440/1024：表单纸面居中，宽度控制在舒适输入范围。
- 768：减少外围装饰与垂直空白。
- 375：容器贴近安全边距，按钮全宽，软键盘出现后主操作仍可到达。

## 不在本页处理

- 不新增第三方登录、短信登录、找回密码或验证流程。
- 不改变 Supabase Auth 配置与注册规则。
- 不把登录页变成营销落地页。

## 验收

- 登录、注册、切换、失败、成功、重复提交和自动填充均有稳定状态。
- 所有字段具备 label、错误关联、键盘焦点和合理 autocomplete。
- 375px 软键盘场景无被遮挡的关键操作。
- 登录页不会触发公共页面内容数据的重复预加载。
