# M07：后台文章预览页设计规格

路由：`/admin/preview/[id]`

源码：`app/admin/preview/[id]/page.tsx` 及现有 `ArticlePreview`

模板：Public-Fidelity Preview

## 页面任务

让博主在发布前以尽可能接近真实文章页的形式校对内容，同时始终知道自己处于后台预览而非公开页面。

## 必须保留

- 通过文章 ID 加载预览内容。
- 对草稿和未公开文章的管理员可见性。
- 现有 `ArticlePreview` 渲染能力。
- 返回编辑器或后台的路径。
- 无文章、无权限和加载失败处理。

## 信息层级

```text
预览状态栏
├── 草稿/预览标识
├── 返回编辑
└── 必要状态信息
公开文章拟真区域
├── 题头与元数据
├── 正文
└── 文章尾部
```

文章内容应获得与公开页相同的阅读权重；后台状态栏必须清晰但不能改变正文排版宽度。

## 版式设计

- 正文区域复用 P03 的 Typography、Article 容器和 Markdown 样式。
- 顶部使用窄而稳定的预览状态栏，避免注入公共 Header 后造成双重导航。
- 草稿标识使用 Badge 与明确文字，不使用大面积警告色覆盖页面。
- 评论、公开互动和无关推荐默认不进入预览，除非当前预览本就验证它们。
- light/dark 必须与公开文章页使用相同 token。

## 组件边界

- `PreviewBar`：预览身份、返回编辑和状态。
- `ArticlePreview`：只渲染文章内容。
- Markdown/Prose、媒体与代码块组件直接复用公开文章页。
- 页面负责权限、文章加载和 not-found，不复制公开文章查询链路。

## 状态

- 加载：状态栏和正文骨架同时稳定出现。
- 不存在：提供返回文章管理的明确路径。
- 无权限：不泄露草稿内容，提供重新登录或返回。
- 数据错误：显示后台错误状态和重试，不伪装成公开 404。
- 编辑器有未保存草稿：按现有数据边界说明预览的是已保存版本还是当前草稿，不能含糊。

## 交互

- 返回编辑保留文章 ID 和现有编辑上下文。
- 内部文章链接可点击，但必须避免让用户误以为已发布。
- 键盘跳过链接可直达预览正文。
- 打印或截图时可隐藏后台状态栏，但屏幕预览必须保留身份标识。
- 不在预览页直接修改文章字段。

## 响应式

- 1440/1024：与公开文章页相同的正文宽度，状态栏横向排列。
- 768：状态栏允许两行，正文宽度不受挤压。
- 375：返回编辑和预览标识始终可见，次要状态折叠；正文与 P03 保持一致。

## 不在本页处理

- 不新增独立发布按钮、评论管理或版本对比工具。
- 不创建第二套 Markdown 渲染和文章样式。
- 不让草稿通过可猜测 URL 绕过权限检查。

## 验收

- 相同文章在预览页和公开页的标题、正文、媒体、代码块宽度一致。
- 草稿、已发布、找不到、无权限和加载失败状态清晰。
- 返回编辑不会丢失目标文章或制造第二次空白加载。
- 375px、dark theme、长代码块和宽图片均不横向溢出。
