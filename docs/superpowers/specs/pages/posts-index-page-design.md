# P02：文章列表页设计规格

路由：`/posts`

源码：`app/posts/page.tsx`、`components/PostList.tsx`

模板：Open Collection

## 页面任务

让访问者快速判断“这里有哪些长文、每篇大致讲什么、何时写成”，并以安静的书目节奏进入阅读，而不是浏览一面营销卡片墙。

## 必须保留

- ArticleNav、PageIntro 和文章总数。
- 编号、日期、标题、摘要和阅读全文入口。
- 当前服务端文章读取、排序和 ISR。
- 中国书目式构图，不改成通用博客卡片网格。

## 信息层级

```text
页面定位：ArticleNav
页面标题：全部文章
辅助说明：总篇数与手记说明
列表主信息：文章标题
列表次信息：日期 / 类型 / 摘要
行动：阅读全文
页尾：篇数与返回入口
```

文章标题必须明显高于摘要；日期和英文类型只承担索引作用，不与标题同权。

## 版式设计

- Default 容器，列表内容宽度与 PageIntro 左右边缘一致。
- PageIntro 到第一篇文章使用一个标准 Section 间距。
- 每篇文章以横向书目条目呈现，编号列宽固定，正文列自适应。
- 条目之间优先用留白和细线区分，不使用独立大阴影。
- 摘要限定合理行数，长标题自然换行，不压缩日期。
- 页尾成为真正的结束节点，不与最后一篇文章粘连。

## 组件边界

- `PostList` 继续拥有文章条目循环。
- 建议将单项提取为 `PostListItem`，只负责条目语义和布局。
- PageIntro 使用 `standard` 变体。
- EmptyState 使用基础组件，不在页面内复制样式。

## 状态

- 正常：显示列表与真实篇数。
- 空：只显示一处 EmptyState，不显示误导性的“加载失败”。
- 服务端读取失败：与真正空列表区分，提供返回首页或刷新入口。
- 预取：文章链接使用 Next 默认预取；评论只在明确阅读意图时预取。

## 交互

- 整个文章条目可点击，但正文中的辅助链接语义保持清楚。
- Hover、Focus 只改变墨色、细线或轻位移，不大幅缩放卡片。
- 键盘焦点覆盖完整条目，并保留可辨认的 focus-visible。

## 响应式

- 1440/1024：编号、正文、日期保持稳定列关系。
- 768：缩小编号列和 gutter，摘要保持可读行长。
- 375：日期移入标题上方或下方的 Metadata 行；标题不小于 H3 移动端规格。
- 超长标题、英文 URL 和连续字符可换行，不制造横向滚动。

## 不在本页处理

- 不新增分类、标签筛选、全文搜索或无限滚动。
- 不改变文章排序和分页策略。
- 不给每篇文章增加封面图要求。

## 验收

- 访问者能在三秒内识别标题、摘要、日期和阅读入口。
- 相邻条目有清晰节奏，但页面没有卡片堆叠感。
- 0、1、10 篇及长标题场景均保持布局稳定。
- 375px 下无横向溢出，焦点与点击区域完整。
