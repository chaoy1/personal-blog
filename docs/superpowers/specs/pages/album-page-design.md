# P05：相册页设计规格

路由：`/album`

源码：`app/album/page.tsx`、`components/Lightbox.tsx`

模板：Paper Collection / Gallery Detail

## 页面任务

让访客先以“册”为单位理解影像主题，再进入册内安静观看照片。页面应像展开的影集与案头相册，而不是电商式图片卡片墙。

## 必须保留

- 相册列表与册内照片两级浏览。
- 封面优先使用相册封面，否则使用首张照片。
- 未归档照片的统一入口。
- 照片日期、说明和灯箱查看能力。
- 返回相册列表后保留当前浏览上下文。
- Phase 2 的预加载快照、缓存和后台刷新规则。

## 信息层级

```text
页面题头
相册索引
└── 封面 / 册名 / 数量 / 时间
相册详情
├── 返回与册名
├── 简介 / 数量 / 时间
└── 照片网格 → 灯箱
```

相册名称是一级信息，数量和时间是索引信息；照片本身在详情视图中成为视觉中心，操作控件退居边缘。

## 版式设计

- 列表态使用有秩序的影集书架，统一封面比例，不用高度随机的瀑布流。
- 封面用纸边、题签和轻微层叠表达“册”，不叠加厚阴影和通用 Card 边框。
- 详情态题头与照片网格共处一张宽宣纸，返回入口靠近册名。
- 图片容器在资源加载前预留比例，避免页面跳跃。
- 横图、竖图通过裁切预览形成稳定网格，灯箱中再显示完整比例。

## 组件边界

- `AlbumShelf`：相册索引与键盘导航。
- `AlbumCover`：封面、题签、数量和日期。
- `AlbumView`：详情题头和照片集合。
- `PhotoGrid`：稳定比例的图片网格。
- `Lightbox`：继续承担放大、前后切换和退出。

相册列表和详情可以保留在同一路由，不为视觉拆分新增不必要的 URL 或数据请求。

## 状态

- 首次预加载：直接显示相册封面和已知尺寸占位。
- 后台刷新：保持当前相册、滚动位置和灯箱状态，不回退到列表。
- 空：没有相册和照片时显示单一 EmptyState。
- 局部空：相册存在但无照片时保留册名与返回入口。
- 错误：有缓存时保留内容并轻量提示；无缓存时提供重试。
- 图片失败：使用固定比例的墨色占位，不让网格塌陷。

## 交互

- 整张封面均可点击，键盘 Enter/Space 可进入。
- 灯箱打开后锁定背景滚动，焦点留在灯箱内，关闭后返回原照片。
- 左右方向键切换照片，Escape 关闭；移动端支持明确的前后按钮。
- 返回相册列表时恢复原滚动位置。
- 后台刷新不覆盖用户正在查看的灯箱索引。

## 响应式

- 1440：相册索引 3–4 列，照片网格 3 列，使用 Wide 容器。
- 1024：相册索引 3 列，照片网格 2–3 列。
- 768：相册索引 2 列，册内信息改为上下排列。
- 375：单列封面或紧凑双列照片；灯箱控件避开系统安全区，说明文字不遮挡主体。

## 不在本页处理

- 不增加公开上传、下载原图、点赞或评论。
- 不改变相册与照片的数据结构、排序规则或存储服务。
- 不把灯箱改造成独立页面。

## 验收

- 列表与详情切换没有额外整页请求造成的空白闪烁。
- 横图、竖图、空相册、破图和大量照片都保持稳定布局。
- 灯箱的键盘、触摸、焦点恢复和 reduced-motion 均可用。
- 375px 下无横向溢出，照片说明和关闭按钮不会相互遮挡。
