# Phase 7 响应式、交互与无障碍设计规格

## 目标

在 Phase 1–6 的页面、数据边界和状态语义基础上，补齐最后一层可操作性契约：键盘用户始终能看见焦点、离开账户页时使用站内确认对话框、关键控件保持可触达，并让移动端布局继续遵守既有断点与根节点不横向溢出约束。

## 范围

- 账户页的“修改完成”离开保护改用共享 `useConfirmDialog`，保留未保存状态、返回触发器和浏览器 `beforeunload` 保护。
- 修复相册卡片、时间轴展开按钮和沉浸式留言输入框的 `:focus-visible` 规则，禁止局部样式移除全局可见焦点环。
- 为这些边界增加可执行测试，覆盖原生确认禁用、焦点环、44px 触达尺寸标记和既有响应式断点。
- 不引入新断点、不改变业务数据协议、不替换山水/书法视觉基调。

## 不在范围内

- 不重写全站 CSS，不进行浏览器自动化截图回归。
- 不调整表单字段语义、认证流程、Supabase schema 或路由结构。

## 验收

- 账户页源码和运行测试均不再依赖 `window.confirm`；脏状态离开由共享 `ConfirmDialog` 处理。
- 相册卡片、时间轴展开按钮、留言输入框的键盘焦点具有明确可见的 `outline`，且不会被 `outline: none/0` 覆盖。
- 既有移动/平板/紧凑桌面/宽桌面断点与根溢出契约保持可发现、可回归。
- 目标测试、全量测试、类型检查和应用路由构建通过。
