# 似水流年网站完整精修设计

日期：2026-08-18

## 目标

在不改变公开站点现有“宋画长卷、昼夜双景、纸墨题签”视觉身份的前提下，完成公开站点与后台的整体精修。重点解决移动端裁切、后台操作不顺、首次展开动画粗糙、加载性能、SEO 与无障碍问题。

成功标准：

- 390px 宽度下没有横向溢出，首页标题、统计、题签和导航均不被裁切。
- 桌面端保留现有首页构图与氛围，不改造成常规卡片式首页。
- 后台采用已确认的 V6 平衡方向：山水背景、松弛稿纸层次、完整顶部操作和原昼夜开关。
- 文章关闭浏览器后可以恢复；已进入服务器草稿阶段的文章可跨设备继续。
- 生产构建、类型检查和关键浏览器流程通过。

## 已确认的视觉方向

### 公开站点

公开站点采用“原貌精修”，不重做首页视觉：

- 保留现有山水背景、主标题、朱砂印、左右竖排题签、每日一句和昼夜切换。
- 修正移动端中 `.verse`、`.sigil`、标题、统计条和引语造成的越界与裁切。
- 内页继续使用同一纸墨语言，只统一间距、可读性、状态和响应式细节。
- 不采用已经否决的“常规首页 + 卡片区”方案。

### 后台

后台采用“山水案头”而非通用仪表盘：

- 使用与前台同源、低对比度的山水背景，加纸雾与纹理保证内容清晰。
- 导航题签和稿件纸页允许轻微错落，保留飘逸、灵活、随性的观感。
- 信息密度以 V6 为基准：保留轻量筛选、搜索、状态和更多操作；统计只在页脚弱化展示。
- 顶部不折叠。桌面端直接排列“查看博客、资料/账户、退出登录、昼夜切换”；保留现有日月拨动按钮。移动端允许自然换行或进入已有移动导航面板，但不使用含糊的省略号菜单代替核心操作。

## 首次画卷展开动画

现有 1.75 秒展开过快，首屏元素几乎同时出现，缺少卷轴重量和层次。新动画采用以下节奏：

1. 先稳定显示宣纸与淡墨山影，避免背景尚未加载就开始。
2. 卷轴在约 2.8–3.2 秒内从左向右展开，速度先缓慢、随后舒展、末端轻收。
3. 纸面卷曲、木杆、阴影和底图揭示分层运动，主要使用 `transform` 与 `opacity`，避免逐帧 JavaScript。
4. 卷过约 65% 后依次出现眉题、主标题、朱砂印、笔触、导语、统计、每日一句和下滑提示；总入场时间控制在约 4.2 秒内。
5. 完整动画只在该浏览器首次访问当前动画版本时播放，使用带版本的 `localStorage` 标记；后续访问只播放约 0.6 秒的轻量淡入。
6. `prefers-reduced-motion: reduce` 时不播放卷轴移动，仅显示最终画面并轻微淡入。
7. 预加载首屏山水图片，并在动画开始前确认关键背景可用，避免卷开后出现空白或跳变。

## 公开站点精修

### 首页与导航

- 以 390px、720px、桌面和矮屏桌面为明确断点重新收束首屏尺寸。
- 移动端隐藏或重新定位超出视口的竖排装饰，所有主内容使用安全内边距。
- 桌面导航保持全部项目可见；移动端全屏导航保留焦点锁定、Esc 关闭、当前页面状态和足够触控面积。
- 搜索、语言、登录和主题控件保持一致的可见状态与键盘焦点样式。

### 内容页面

- 文章正文限制舒适行宽，统一标题、引用、代码块、表格、图片说明和长链接换行。
- 优化阅读进度、返回路径、图片灯箱和移动端触控。
- 文章、闲语、光影、时间轴、留言和关于页共享间距、纸面和状态规范，但保留各自布局节奏。
- 表单提供提交中、成功、失败和重试状态；不只依赖颜色表达状态。

## 后台操作设计

### 统一交互基础

建立可复用的后台交互层：

- 统一的加载状态、按钮忙碌状态、行内错误、成功提示和可撤销通知。
- 用站内确认对话框替代 `window.confirm`，危险操作明确对象和后果。
- 能恢复的删除先软删除或提供短时撤销；永久删除需要二次确认。
- 页面离开前检测未保存更改；提交失败时保留用户输入。

### 文章与双重暂存

- 输入变化立即写入本地备份，键包含文章 ID 或新文章临时 ID、更新时间与内容摘要。
- 用户停止输入约 1.5 秒后同步服务器草稿；新文章在标题可用后创建未发布记录，之后持续更新同一记录。
- 手动“保存草稿”和“发布”会立即刷新待保存内容，避免最后几个字符丢失。
- 打开编辑器时比较本地与服务器时间；本地更新则提示恢复、查看差异或忽略，禁止静默覆盖。
- 保存草稿后停留在编辑器并显示“已保存于 HH:mm”；发布成功后提供查看文章与继续编辑入口。
- 草稿预览使用受保护的后台预览路径，不要求先公开文章。
- 浏览器关闭后，同一设备可从本地恢复；已同步的服务器草稿可跨设备继续。

### 闲语

- 保留现有本地暂存，统一到新的草稿状态组件。
- 增加编辑已发布闲语、图片上传进度、失败重试与删除撤销。
- 上传期间逐张反馈，不以一个模糊的“处理中”覆盖所有状态。

### 光影与相册

- 文件选择后先进入批量预览区，再确认上传。
- 每张照片可单独填写说明、选择相册、移除或重试。
- 支持修改说明、移动相册和排序。
- 相册可编辑标题与说明；删除时明确照片只会移出相册，不会删除原图记录。

### 资料与登录

- 资料页显示未保存状态、保存结果和前台效果入口。
- 登录失败保留清晰错误；登录成功返回原本想访问的后台页面。
- 顶部退出操作直接可见，退出前不需要额外确认。

## 性能设计

- 审查并减少不必要的客户端组件、全局监听和持续动画。
- 不可见时暂停星空、枫叶、视差和粒子效果；低性能设备降低粒子数量。
- 首屏只优先加载关键背景和字体，内页图片使用合适尺寸、懒加载与稳定宽高，减少布局跳动。
- 合并或删除重复、互相覆盖的 CSS 规则，将公开站点变量、后台变量和响应式覆盖分层整理。
- 首页数据继续并行读取；为失败区块保留独立降级，不让单个接口拖垮整页。

## SEO 与无障碍

- 为公开页面提供独立标题、描述、canonical、Open Graph 和分享图配置。
- 为文章输出 Article 结构化数据，并增加 `sitemap.ts` 与 `robots.ts`；后台继续禁止索引。
- 保证导航、菜单、灯箱、对话框、分页、上传和编辑工具条可使用键盘。
- 补齐焦点可见样式、对话框焦点管理、表单标签、状态播报和图片替代文本。
- 校验昼夜主题的正文、弱文字、边框和按钮对比度。

## 代码边界

- 保留 Next.js App Router 与 Supabase 架构，不引入新的外部服务。
- 公共视觉组件、后台反馈组件、草稿存储逻辑和上传状态逻辑分开实现，避免继续扩大页面组件。
- 暂存优先复用现有 `posts` 未发布记录；不为普通自动保存引入新的数据库表。
- 如果实现排序需要持久字段，只添加最小的 `sort_order` 数据库迁移并保持旧数据兼容。

## 错误与恢复

- 网络失败不清空编辑内容、待上传文件或表单输入。
- 自动保存失败显示非阻断提示并继续保留本地版本；连接恢复后允许重试。
- 上传部分失败时保留成功项和失败项，用户可以只重试失败项。
- 会话失效时保留本地草稿，登录后回到原页面继续操作。

## 验证方案

- 运行 `npm run typecheck` 与 `npm run build`。
- 浏览器检查公开首页、文章、闲语、光影、时间轴、留言、关于、登录和账户页面。
- 检查桌面、390px 移动端、矮屏桌面、昼夜主题和减少动态效果模式。
- 验证首次完整画卷展开、后续轻量入场和动画版本更新行为。
- 验证文章本地恢复、服务器自动保存、冲突提示、保存草稿、预览和发布。
- 验证闲语编辑与撤销、相册批量上传与部分失败、资料保存和会话失效恢复。
- 检查键盘导航、焦点顺序、对话框焦点锁定、状态播报、页面元数据、站点地图与 robots。

## 非目标

- 不更换技术栈、数据库服务或部署平台。
- 不重做公开首页的视觉身份。
- 不加入访问统计、订阅、商业化或多作者权限系统。
- 不将后台改造成数据密集型通用仪表盘。
