# Phase 8 清理与统一设计规格

## 目标

在 Phase 7 回归基线稳定后，只清除已被确认无效的历史样式实现，并把维护边界写成可审计文档。清理必须是局部、可逆、可验证的：不以“看起来重复”为理由删除仍承担基础样式的声明。

## 确认的清理项

- `app/guestbook/guestbook.css` 中前置的 `.guestbook-immersive-textarea:focus-visible` 是后置同名规则的完全覆盖实现，删除前置块；焦点规则只保留最终沉浸式纸笺实现。
- 最终焦点规则保留明确的 `outline` 与偏移，避免清理把 Phase 7 修复重新覆盖。
- 兼容性 facade（`lib/app-store.tsx`）以及旧变量不删除；它们仍由测试和迁移边界明确保护。

## 维护规则

- `globals.css` 保留 reset、token 与跨页面基础契约。
- `refinement.css` 保留共享组件和全站细化。
- 页面专属 CSS 只保留页面结构、视觉配方和局部响应式覆盖。
- 删除 CSS 前必须同时满足：选择器有明确后置所有者、无独立声明依赖、目标测试覆盖清理结果。

## 验收

- 留言焦点选择器在源码中只有一个实现，最终规则包含可见焦点环。
- 清理不改变留言表单 DOM、状态语义或提交行为。
- 维护文档记录本次删除、保留的兼容层和验证命令。
